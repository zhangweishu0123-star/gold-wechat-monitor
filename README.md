# 黄金微信盯盘 V2：带“已完成 / 未完成”交互

这版解决你刚刚指出的核心问题：

**提醒了 ≠ 你真的执行了。**

系统以后不会因为自己发过“卖20g”，就默认你已经卖了。

## 新逻辑

微信提醒会变成：

```text
当前价：958.30元/g
操作：卖20g

当前仓位：675.5714g
如果执行：655.5714g

✅ 已完成
❌ 未完成
```

- 点 **已完成**：系统才真的把仓位扣掉20g，并更新现金估算。
- 点 **未完成**：仓位完全不变。
- 如果你没卖20g，后面价格直接涨到970，系统不会只告诉你“再卖30g”，而是会按“目标累计卖50g - 已确认卖出0g”，重新告诉你 **卖50g**。
- 如果你已经确认卖了20g，再涨到970，则只会提醒你 **再卖30g**。

买入同理：

- 930档目标累计买10g
- 910档目标累计买30g
- 899及以下目标累计买60g

例如930时提醒买10g但你没买，后来跌到910，系统会按真实状态提醒 **买30g**；如果930那10g你已经确认完成，则910只提醒 **再买20g**。

这就是“目标仓位制”，比“看到价格就机械固定买卖量”更适合你。

---

## 为什么 V2 改成 Cloudflare Workers

V1 的 GitHub Actions 很适合“单向提醒”，但不适合让你在微信里确认后立即改变仓位状态。

V2 使用：

- Cloudflare Worker：每5分钟读一次京东报价
- Durable Object：保存你的真实确认仓位
- PushPlus：发到微信
- 微信消息中的两个链接：确认“已完成 / 未完成”

Cloudflare Durable Objects 是有状态服务，所以系统能记住你到底有没有执行上一笔。

# 部署步骤

## 0. 先确认初始数据

我已经先按目前这版填了：

```text
持仓：675.5714g
现金：80000元
核心仓底线：575g
现金底线：25000元
卖出手续费估算：0.4%
```

都在 `wrangler.jsonc` 里。

**如果你真正部署时仓位已经变化，先改这两个：**

```json
"START_HOLDINGS_G": "675.5714",
"START_CASH_YUAN": "80000"
```

首次运行后，系统会把状态保存在 Durable Object 中；之后不会每次都用这里的初始值覆盖。

```bash

```

没有 Cloudflare 账号的话按页面注册即可。

```bash

```

成功后会给你一个类似：

```text

```

的地址。

---

## 6. 设置 PushPlus Token

**Token 不要写进代码。**

运行：

```bash
npx wrangler secret put PUSHPLUS_TOKEN
```

终端会让你输入 Secret Value。

粘贴你的 PushPlus Token，回车即可。

Cloudflare 会把它作为加密 Secret 保存。

---

## 7. 再打开一次 Worker 地址

浏览器打开刚才的：

```text
https://gold-wechat-monitor.xxxxx.workers.dev
```

看到：

```text
✅ 黄金微信盯盘 V2 已启动
```

即可。

这一步会让系统记住自己的地址，之后微信里的“已完成 / 未完成”按钮才能回到你的 Worker。

---

## 8. 等待真实提醒

系统每5分钟检查一次。

注意：

- 940～955：不发操作提醒。
- 报价超过15分钟没有刷新：不发交易指令。
- 只有需要你真正买卖时才推微信。
- 微信提醒30分钟没有处理，同一档位才可能再次提醒。
- 如果价格跨到新档位，旧提醒会作废，新提醒会按“真实已确认仓位”重新计算。

# 卖出逻辑：不再是“固定每档卖多少”，而是“目标累计卖多少”

| 当前价 | 本轮上涨目标累计卖出 |
|---|---:|
| 955～965 | 20g |
| 965～980 | 50g |
| 980～1000 | 80g |
| >=1000 | 100g |

所以：

- 960提醒卖20g，你点“已完成”
- 970时：只需要再卖30g

但如果：

- 960提醒卖20g，你点“未完成”
- 970时：系统直接提醒卖50g

系统不会假装你已经执行。

---

# 买入逻辑：目标累计买入

| 当前价 | 本轮下跌目标累计买入 |
|---|---:|
| 920～940 | 10g |
| 900～920 | 30g |
| <=900 | 60g |

系统同时检查现金底仓。

如果按推荐买完会让现金低于25000元，系统会自动缩小买入量，绝不会按原计划把现金打光。

---

# “已完成”后的仓位如何更新？

买入完成：

```text
持仓 += 买入克数
现金 -= 克数 × 提醒时金价
```

卖出完成：

```text
持仓 -= 卖出克数
现金 += 克数 × 提醒时金价 × (1 - 0.4%)
```

因此：

**克数仓位是精确跟着你的确认走的；现金目前是估算值。**

因为你实际点击下单时的成交价可能和提醒价差几毛钱。

以后如果你需要，我还可以继续升级为：

“点已完成以后，再填一次实际成交价”

这样连现金和每一笔真实收益都能完全准确。

---

# 安全保护

1. 每一条“已完成 / 未完成”链接都有随机一次性 token。
2. 老提醒被新提醒替代后，再点老提醒只会提示“已过期”，不会改仓位。
3. 卖出永远不会把总持仓降到575g以下。
4. 买入永远不会把估算现金降到25000元以下。
5. 报价滞后超过15分钟时不发操作指令。
6. 系统只提醒，不会连接京东账户，不会自动下单。

---

# PushPlus消息展示说明

PushPlus 的微信渠道默认使用微信公众号模板消息；打开消息后会进入 H5 详情页。V2 在详情内容中放“已完成 / 未完成”链接。

也就是说体验是：

**微信收到提醒 → 点开消息 → 点一下“已完成”或“未完成” → 状态更新。**

不是自动读取你的京东成交记录。
